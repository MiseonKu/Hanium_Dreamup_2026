# IMU + Vive Tracker 기반 End-Effector 위치 추정 실험 절차

## 0. 실험 목적

본 실험의 목적은 로봇 관절 또는 링크에 부착된 IMU 센서 데이터를 이용하여 로봇 end-effector의 위치를 추정하는 supervised learning 모델을 개발하는 것이다.

학습 단계에서는 Vive Tracker 3.0을 end-effector에 부착하여 ground truth 위치 데이터를 얻고, IMU 데이터와 동기화하여 학습 데이터셋을 구성한다.

추론 단계에서는 Vive Tracker 없이 IMU 데이터만을 입력으로 받아 end-effector의 위치를 실시간으로 추정하는 것을 목표로 한다.

기본 목표 구조는 다음과 같다.

```text
학습 시:
IMU raw/processed time-series + Vive Tracker ground truth
→ supervised learning

추론 시:
IMU time-series only
→ predicted end-effector position
````

최종적으로 학습된 모델은 RTX 4060 PC에서 학습하고, NVIDIA Jetson AGX Orin 64GB에 배포하여 실시간 추론 성능을 검증한다.

---

## 1. 전체 시스템 구성

### 1.1 사용 장비

* Robot manipulator
* Vive Tracker 3.0
* Base Station
* WT901C IMU 3개 이상
* Robot joint encoder
* RTX 4060 학습용 PC
* Jetson AGX Orin 64GB 추론용 장비

### 1.2 센서 부착 위치

* Vive Tracker 3.0

  * 로봇 end-effector에 단단히 고정
  * 실험 중 tracker가 흔들리거나 미끄러지지 않도록 고정

* IMU

  * 로봇의 주요 관절 또는 링크에 부착
  * 각 IMU는 실험 중 움직이지 않도록 단단히 고정
  * 케이블 장력으로 IMU가 흔들리지 않도록 정리

* Encoder

  * 각 관절의 실제 joint angle 또는 motor position 기록

## 2. 데이터 역할 정의

실험에서 수집하는 데이터는 모두 저장하지만, 학습에 사용하는 역할은 분리한다.

### 2.1 IMU 데이터

IMU 데이터는 모델의 주요 입력으로 사용한다.

추론 시에도 사용할 수 있는 정보이므로 학습 입력에 포함 가능하다.

예시 입력:

```text
acceleration
angular velocity
quaternion
Euler angle
magnetometer
temperature
status
```

단, 학습 모델에 실제로 넣을 feature는 후처리 단계에서 선택한다.

---

### 2.2 Vive Tracker 데이터

Vive Tracker 데이터는 end-effector의 ground truth label로 사용한다.

중요한 원칙:

```text
Vive Tracker 데이터는 학습 입력으로 넣지 않는다.
Vive Tracker 데이터는 정답 label로만 사용한다.
```

잘못된 구조:

```text
IMU + Vive Tracker pose → model → end-effector position
```

올바른 구조:

```text
IMU time-series → model → predicted end-effector position
predicted position ↔ Vive Tracker position 비교
```

---

### 2.3 Encoder 데이터

Encoder 데이터는 다음 용도로 사용한다.

* FK baseline 계산
* joint angle ground truth 또는 보조 label
* IMU 기반 joint angle 추정 모델 검증
* 데이터 이상 여부 확인
* D-H 파라미터 기반 FK 결과와 Vive Tracker 결과 비교

최종 추론에서 encoder를 사용할지 여부에 따라 학습 입력 사용 여부를 결정한다.

#### Case A: 최종 목표가 IMU only 추론인 경우

```text
입력:
IMU only

정답:
Vive Tracker xyz

Encoder:
검증 / 보조 label / FK baseline 용도
```

이 경우 encoder를 학습 입력에 넣지 않는다.

#### Case B: 최종 시스템에서 encoder도 사용할 수 있는 경우

```text
입력:
IMU + Encoder

정답:
Vive Tracker xyz
```

또는 다음 구조를 사용할 수 있다.

```text
Encoder + D-H/FK → FK_xyz
IMU → neural correction Δxyz
Final prediction = FK_xyz + Δxyz
```

---

## 3. D-H 파라미터와 IK Solver의 역할

### 3.1 D-H 파라미터

D-H 파라미터는 로봇의 기구학적 구조를 표현하는 정보이다.

D-H 파라미터는 일반적인 센서 feature처럼 매 timestep마다 모델에 넣기보다는, Forward Kinematics 계산 모듈로 사용하는 것이 적절하다.

추천 구조:

```text
IMU time-series
→ neural network
→ estimated joint angles
→ D-H / FK
→ predicted end-effector xyz
→ Vive Tracker xyz와 비교
```

또는 encoder를 사용하는 경우:

```text
Encoder joint angles
→ D-H / FK
→ FK_xyz

IMU time-series
→ model
→ correction Δxyz

Final xyz = FK_xyz + Δxyz
```

---

### 3.2 IK Solver

IK Solver는 학습 입력으로 직접 넣는 것보다 다음 용도로 사용하는 것이 적절하다.

* 랜덤 end-effector target 생성
* target pose에 대응하는 joint target 계산
* workspace를 균일하게 커버하는 trajectory 생성
* Vive Tracker pose로부터 pseudo joint label 생성
* FK/IK consistency 검증

주의할 점:

```text
Vive Tracker xyz → IK Solver → 모델 입력
```

이 구조는 피해야 한다.

이 경우 학습 때는 정답 정보를 이용한 값을 모델 입력에 넣는 것이므로, 추론 시 Vive Tracker가 없을 때 동작하지 않을 수 있다.

원칙:

```text
추론 때 사용할 수 없는 정보는 학습 입력에도 넣지 않는다.
```

## 4. 실험 절차 개요

전체 실험 절차는 다음과 같다.

```text
1. Init pose로 이동
2. Runtime cache 및 sensor buffer 초기화
3. IMU / Vive Tracker / Encoder raw data 수집 시작
4. 로봇 랜덤 trajectory 수행
5. 각 trajectory 후 0.5~1.0초 정지
6. 최소 1,500회 이상 반복
7. Raw data 저장
8. 시간 동기화 및 후처리
9. 학습용 dataset 생성
10. Supervised learning 수행
11. 모델 export
12. AGX Orin에 배포
13. 실시간 tracking 성능 검증
```

## 5. 상세 실험 절차

## Step 1. Init pose 이동 및 초기화

로봇을 항상 동일한 init pose로 이동시킨다.

Init pose는 모든 실험 세션에서 동일해야 하며, IMU와 tracker의 기준값을 잡는 기준 자세로 사용한다.

### 5.1 Init pose 조건

* 로봇이 완전히 정지한 상태
* 모터 holding 상태 안정화
* IMU가 흔들리지 않는 상태
* Vive Tracker tracking 상태 valid
* Encoder 값 안정화

### 5.2 초기화 시 저장할 값

각 세션 시작 시 다음 값을 저장한다.

```text
IMU:
- q_init
- gyro_bias
- accel_init
- optional magnetometer init value

Vive Tracker:
- p_tracker_init
- q_tracker_init
- tracking status

Encoder:
- joint_angle_init

System:
- session_id
- robot_id
- sensor configuration
- IMU mounting position
- sampling rate
- timestamp 기준
```

### 5.3 Init 기준 상대값 변환

IMU orientation은 init pose 기준 상대 orientation으로 변환한다.

```text
q_rel = inverse(q_init) * q_current
```

Gyro는 init 상태에서 평균 bias를 빼준다.

```text
gyro_corrected = gyro_raw - mean_gyro_during_init
```

Vive Tracker 위치도 init 기준 상대 위치로 변환할 수 있다.

```text
p_ee_rel = p_ee_current - p_ee_init
```

초기 목표는 absolute xyz보다 init-relative xyz를 예측하는 것이 더 쉽다.

추천 출력:

```text
model output = [dx, dy, dz]
```

## Step 2. Raw data 수집 시작

수집 시작 후에는 모든 센서 데이터를 timestamp와 함께 저장한다.

중요한 원칙:

```text
수집은 가능한 한 전부 저장한다.
학습 입력은 후처리 단계에서 선택한다.
```

### 5.4 저장할 데이터 종류

* IMU raw data
* IMU processed data
* Vive Tracker raw pose
* Encoder raw data
* Robot command
* Target joint angle
* Target end-effector pose
* Event marker
* Tracking status
* Error / warning status

---

## Step 3. 로봇 랜덤 이동

로봇은 무작위 target을 향해 반복적으로 이동한다.

단, 진짜 완전 랜덤 명령을 직접 모터에 넣는 것은 위험하므로 다음 조건을 만족해야 한다.

### 5.5 랜덤 trajectory 조건

* joint limit 준수
* velocity limit 준수
* acceleration limit 준수
* self-collision 방지
* singularity 영역 회피
* workspace 전체를 골고루 커버
* 부드러운 trajectory 사용

추천 방식:

```text
1. random joint target 생성
2. joint limit / collision check
3. cubic trajectory 또는 minimum jerk trajectory 생성
4. 로봇 이동
5. 이동 중 모든 센서 데이터 저장
6. 도착 후 0.5~1.0초 정지
7. 다음 target 생성
```

또는 IK Solver를 사용하는 경우:

```text
1. random end-effector target 생성
2. IK Solver로 joint target 계산
3. 유효한 IK 해인지 확인
4. 로봇 이동
5. 데이터 저장
```

---

## Step 4. 이동 후 정지 구간 저장

각 랜덤 이동 후 0.5초 이상 정지 구간을 둔다.

추천 정지 시간:

```text
minimum: 0.5초
recommended: 1.0초
```

정지 구간은 다음 목적에 유용하다.

* 안정 pose에서 IMU와 Vive 좌표 관계 확인
* gyro bias 안정성 확인
* encoder-FK와 Vive Tracker 위치 비교
* 동적 구간과 정적 구간 성능 분리 평가

단, 실시간 tracking 모델을 만들기 위해서는 정지 구간뿐 아니라 이동 중 데이터도 반드시 학습에 포함해야 한다.

정지 데이터만 학습하면 움직이는 중의 tracking 성능이 떨어질 수 있다.

---

## Step 5. 반복 횟수

최소 1,500회 이상의 랜덤 이동을 수행한다.

예상 데이터 수는 다음과 같다.

예를 들어:

```text
average moving time = 2.0 sec
stop time = 0.5 sec
sampling rate = 100 Hz
repeat = 1,500
```

그러면 timestep 수는 다음과 같다.

```text
2.5 sec × 100 Hz × 1,500 = 375,000 timesteps
```

Sliding window를 적용하면 학습 샘플 수는 더 많아진다.

단, 중요한 것은 단순 sample 수보다 데이터 분포이다.

좋은 데이터 조건:

```text
joint angle 범위가 골고루 포함됨
workspace 전체가 포함됨
느린 움직임과 빠른 움직임이 모두 포함됨
가속 / 감속 / 정지 상태가 모두 포함됨
여러 session으로 나누어 수집됨
```

## 7. Timestamp 정책

모든 데이터에는 PC 기준 monotonic timestamp를 찍는다.

추천 timestamp:

```text
t_pc_ns = time.perf_counter_ns()
```

또는:

```text
t_pc_ns = time.monotonic_ns()
```

`datetime.now()` 기반 timestamp는 시스템 시간 변경에 영향을 받을 수 있으므로 동기화용 기준 timestamp로는 부적절할 수 있다.

### 7.1 Timestamp 사용 목적

Timestamp는 모델 입력으로 넣는 것이 아니라, 주로 다음 용도로 사용한다.

* IMU와 Vive Tracker 시간 정렬
* Encoder와 IMU 시간 정렬
* sensor latency 추정
* resampling
* interpolation
* sliding window 생성
* packet loss 확인

원칙:

```text
absolute timestamp는 모델 입력으로 넣지 않는다.
```

필요한 경우 `dt` 정도만 입력 feature로 사용할 수 있다.

## 10. 시간 동기화

IMU, Vive Tracker, Encoder는 서로 다른 주기로 데이터가 들어올 수 있다.

따라서 기준 sampling rate를 정해야 한다.

예시:

```text
target sampling rate = 100 Hz
target dt = 0.01 sec
```

각 timestamp에 대해 다음 데이터를 정렬한다.

```text
target time t
IMU data near t
Vive Tracker pose interpolated at t
Encoder angle interpolated at t
```

Vive Tracker 위치는 IMU timestamp 기준으로 interpolation한다.

---

## 11. 좌표계 정렬

최소 세 가지 좌표계가 존재한다.

```text
SteamVR / Vive coordinate frame
Robot base coordinate frame
IMU sensor coordinate frame
```

가능하면 Vive Tracker 위치를 robot base 기준 좌표계로 변환한다.

변환 식:

```text
p_base = R_base_vive * p_vive + t_base_vive
```

이 작업을 하지 않으면 base station 위치가 바뀌거나 로봇 위치가 바뀌었을 때 모델이 무너질 수 있다.

## 12. 학습용 Dataset 생성

학습 sample은 시계열 window 단위로 생성한다.

예시:

```text
X = recent 1.0 sec IMU time-series
y = current end-effector position from Vive Tracker
```

IMU 3개, 100Hz, 1초 window, IMU당 10개 feature를 쓰는 경우:

```text
X shape = [100, 30]
y shape = [3]
```

여기서 30은 다음과 같다.

```text
IMU 1개당:
q_rel_w, q_rel_x, q_rel_y, q_rel_z,
gyro_x, gyro_y, gyro_z,
accel_x, accel_y, accel_z

총 10개 × 3개 IMU = 30 features
```

## 14. 학습 Label

초기 추천 label:

```text
y = [dx, dy, dz]
```

여기서:

```text
dx, dy, dz = init pose 대비 end-effector 위치 변화량
```

즉:

```text
p_ee_rel = p_ee_current - p_ee_init
```

나중에 절대 좌표가 필요하면 다음과 같이 복원한다.

```text
p_ee_abs = p_ee_init + p_ee_rel_predicted
```

## 15. Train / Validation / Test Split

절대 timestep 단위로 랜덤 split하지 않는다.

나쁜 방식:

```text
전체 timestep을 랜덤 셔플하여 train/test 분리
```

이 방식은 인접한 timestep이 train과 test에 동시에 들어갈 수 있어 성능이 과대평가된다.

좋은 방식:

```text
session 단위 split
trajectory 단위 split
workspace 구간 단위 split
```

예시:

```text
session_001 ~ session_010: train
session_011 ~ session_012: validation
session_013 ~ session_014: test
```

또는:

```text
trajectory 1~1200: train
trajectory 1201~1350: validation
trajectory 1351~1500: test
```

## 16. 모델 학습 전략

처음부터 복잡한 모델을 사용하지 않고 baseline부터 순서대로 실험한다.

---

### 16.1 Baseline A: IMU → xyz 직접 예측

가장 단순한 baseline이다.

```text
IMU time-series
→ TCN / GRU / MLP
→ predicted [dx, dy, dz]
```

장점:

```text
구현이 쉽다.
전체 파이프라인 검증에 좋다.
```

단점:

```text
로봇의 기구학 구조를 직접 반영하지 않는다.
데이터가 부족하면 일반화 성능이 떨어질 수 있다.
```

---

### 16.2 Baseline B: IMU → joint angle → FK → xyz

로봇 구조를 반영한 모델이다.

```text
IMU time-series
→ neural network
→ estimated joint angles
→ D-H / FK
→ predicted end-effector xyz
→ Vive Tracker xyz와 비교
```

장점:

```text
로봇 구조를 반영한다.
모델이 end-effector 위치를 통째로 외울 필요가 줄어든다.
```

단점:

```text
IMU로 joint angle을 잘 추정해야 한다.
IMU 부착 오차와 yaw drift에 민감할 수 있다.
```

---

### 16.3 Baseline C: FK + Neural Residual

Encoder 사용이 가능한 경우 추천하는 구조이다.

```text
Encoder
→ D-H / FK
→ FK_xyz

IMU time-series
→ neural network
→ correction Δxyz

Final prediction = FK_xyz + Δxyz
```

장점:

```text
FK가 큰 위치를 맞춘다.
모델은 오차 보정만 담당한다.
실전 성능이 좋을 가능성이 높다.
```

보정 대상 예시:

```text
센서 부착 오차
기구 오차
백래시
링크 휨
캘리브레이션 오차
Vive 좌표계 정렬 오차
진동
```

## 17. Loss Function

초기 loss는 MSE 또는 MAE를 사용한다.

기본 loss:

```text
loss = MSE(pred_xyz, target_xyz)
```

또는:

```text
loss = MAE(pred_xyz, target_xyz)
```

동적 tracking 성능을 높이려면 velocity loss를 추가할 수 있다.

```text
loss = position_loss + λ * velocity_loss
```

velocity loss:

```text
velocity_pred = pred_xyz[t] - pred_xyz[t-1]
velocity_gt = target_xyz[t] - target_xyz[t-1]
velocity_loss = MSE(velocity_pred, velocity_gt)
```

## 18. 평가 지표

평균 오차만 보지 말고 여러 지표를 함께 확인한다.

추천 지표:

```text
MAE_x
MAE_y
MAE_z
3D position RMSE
3D position MAE
95 percentile error
max error
static error
dynamic error
velocity-dependent error
workspace-region error
latency
inference FPS
```

3D position error:

```text
error_3d = sqrt((x_pred - x_gt)^2 + (y_pred - y_gt)^2 + (z_pred - z_gt)^2)
```

결과 예시:

```text
Mean error: 12 mm
RMSE: 18 mm
95% error: 42 mm
Max error: 91 mm
Latency: 6 ms
Inference rate: 100 Hz
```

로봇 제어에 사용할 경우 평균 오차보다 95 percentile error와 max error가 더 중요하다.

## 19. Ablation Study

처음부터 feature를 하나로 고정하지 말고 여러 조합을 비교한다.

추천 실험:

```text
A: accel + gyro

E: gyro + quaternion
```

## 20. Sanity Check

본격 학습 전에 작은 데이터셋으로 파이프라인 검증을 한다.

### 20.1 소량 데이터 overfit test

2~3분 데이터만 사용해서 모델이 overfit 되는지 확인한다.

```text
작은 dataset에서 loss가 충분히 내려가야 한다.
```

만약 작은 데이터셋에서도 loss가 내려가지 않으면 다음 문제를 의심한다.

```text
timestamp mismatch
Vive와 IMU 시간 지연
좌표계 변환 오류
quaternion 순서 오류
단위 오류
IMU 부착 방향 오류
Vive tracking invalid 구간 포함
label 생성 오류
```

## 24. 주요 위험 요소

### 24.1 시간 동기화 문제

IMU와 Vive Tracker의 timestamp가 맞지 않으면 모델이 잘못된 관계를 학습한다.

예:

```text
IMU는 현재 자세
Vive label은 50ms 이전 위치
```

이 경우 학습 성능이 크게 떨어진다.

---

### 24.2 좌표계 문제

Vive 좌표계와 robot base 좌표계가 맞지 않으면 모델이 특정 실험 환경에만 과적합될 수 있다.

---

### 24.3 IMU 부착 문제

IMU가 실험 중 흔들리면 모델이 실제 로봇 움직임이 아니라 센서 흔들림을 학습한다.

---

### 24.4 Magnetometer 간섭

로봇 모터, 금속 프레임, 전류로 인해 magnetometer와 yaw 값이 오염될 수 있다.

따라서 magnetometer 포함/제외 실험을 반드시 비교한다.

---

### 24.5 데이터 분포 문제

랜덤 trajectory가 충분히 다양하지 않으면 모델이 특정 움직임만 잘 맞히고 새로운 자세에서는 틀릴 수 있다.

## 26. 최종 정리

본 실험에서 가장 중요한 원칙은 다음과 같다.

```text
Raw data는 가능한 한 전부 저장한다.
학습 입력에는 추론 때 사용할 수 있는 정보만 넣는다.
Vive Tracker는 정답 label로만 사용한다.
D-H 파라미터는 FK 계산 모듈로 사용한다.
IK Solver는 trajectory 생성 또는 보조 label 용도로 사용한다.
Encoder는 최종 시스템에서 쓸 수 있는지에 따라 입력 여부를 결정한다.
Train/test split은 session 또는 trajectory 단위로 한다.
모델보다 timestamp, 좌표계, 센서 부착, 데이터 분포가 더 중요하다.
```

최종 목표 구조:

```text
IMU time-series
→ model
→ predicted end-effector position
→ Orin real-time inference
```

확장 목표 구조:

```text
IMU time-series
→ estimated joint angles
→ D-H / FK
→ predicted end-effector position
```

또는:

```text
Encoder + D-H/FK → FK_xyz
IMU time-series → correction Δxyz
Final xyz = FK_xyz + Δxyz
```
